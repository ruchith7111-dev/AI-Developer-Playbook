# Contributing

Thanks for helping improve this playbook.

## Useful contributions
- Practical guidance readers can apply.
- Clear explanations of why a practice matters.
- Small examples, diagrams, exercises, and checklists.
- Reliable links to primary documentation.
- Honest limitations and version notes.

## Before opening a change
1. Search for an existing guide to avoid duplication.
2. Keep one topic per pull request where possible.
3. Prefer concise examples over generic advice.
4. Verify links and describe external resources accurately.
5. Never include secrets, private data, or copyrighted text copied from others.

## Suggested guide structure
- What the concept means.
- When useful—and when not.
- A concrete example.
- A prompt or workflow to try.
- How to verify the result.
- Common failure modes.
- Further reading.

## Diagrams and media
Original SVG diagrams are welcome. Keep text readable, add accessible titles/descriptions, and store source in assets/. For videos, link to the original creator or official documentation. Do not upload videos you do not own.

## Style
Use plain language, descriptive headings, fenced code blocks, and relative repository links. Avoid claims such as “always works” or “guaranteed secure”.

## Pull requests
Explain the problem, summarize the change, list links checked, and include previews when visual assets change.
