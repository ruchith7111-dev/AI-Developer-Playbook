# Before-coding checklist

## Product clarity
- [ ] User and problem are clear.
- [ ] Desired behavior is written down.
- [ ] Acceptance criteria are observable.
- [ ] Non-goals and unknowns are listed.

## Project context
- [ ] Assistant inspected the existing repository.
- [ ] Relevant architecture and data contracts are available.
- [ ] Conventions and tests are understood.
- [ ] Runtime, framework, and dependency constraints are known.

## Safety
- [ ] No secrets or unnecessary personal data are in prompts.
- [ ] Task does not require production access.
- [ ] Tool permissions match the task.
- [ ] Destructive/external actions require approval.

## Execution
- [ ] Task is split into reviewable slices.
- [ ] In-scope and out-of-scope files are clear.
- [ ] Tests and verification are identified.
- [ ] Rollback path exists for risky changes.

**Ready when:** a reviewer can tell whether the result is correct.
